# Local AI collection automation

## Goal and completion criteria
Extend Bruno's existing AI preferences and import dialog with subscription-authenticated local Codex / Claude Code CLI configuration, connection checks, and a Swagger/OpenAPI link to AI-organized Bruno collection workflow. Preserve all existing import and AI API-key behavior. Import covers folder organization, server/baseUrl environments, declared authentication, and safe generated token-capture response scripts for documented login endpoints. User credentials stay in Bruno; authentication requests are executed by the user after import.

## Scope and assumptions
- Local Electron is the target; no external deployment or new dependencies.
- Installed CLIs use their existing account login. Settings offer executable path, model override, enable toggle, preferred import provider, and check connection; they do not copy CLI credentials.
- Accept HTTP(S) JSON/YAML specs and discover specs from common Swagger UI HTML/config links without executing HTML. Report unresolved/external references rather than silently missing endpoints.
- Send a compact structural OpenAPI summary to AI, excluding literal example/default secret values. AI returns a constrained JSON organization/token plan. Existing converters and deterministic application own final collection generation. No arbitrary AI-generated executable scripts are accepted.
- Run a bundled application skill as prompt instructions, separate from global user skills. No global skill installation required.
- No live application credentials or login POSTs are sent during import. Generated response script captures a token after the user runs the login request; unknown token paths are reported for review.
- Existing import destination/format selection remains; AI import returns a Bruno collection using the existing save pipeline.

## Shared IPC contract (leader owns registration)
- `renderer:ai-local-status` -> `{ providers: [{ id: 'codex'|'claude', label, enabled, executable, model }], preferredProvider }` (configuration only).
- `renderer:ai-local-test` payload `{ providerId }` -> `{ ok, version?, authenticated?, error? }`; executable and model come exclusively from saved preferences.
- `renderer:ai-import-openapi` payload `{ url, providerId?, requestId }` -> `{ collection, summary: string[], warnings: string[], sourceUrl }`; no filesystem writes.
- `renderer:ai-import-cancel` invoke payload `{ requestId }` -> cancellation acknowledgement. Jobs are scoped to sender and cancelled on window teardown.
- Throw actionable errors for disabled AI/provider, missing CLI/login, timeout, malformed AI output, invalid/unresolvable spec.
- Preferences `ai.localProviders = { preferredProvider: 'codex', codex: { enabled:false, executable:'codex', model:'' }, claude: { enabled:false, executable:'claude', model:'' } }`.
- Main backend module exports `registerLocalAiIpc(mainWindow)` from `ipc/ai/local.js`; leader calls it from existing AI registration. Local provider settings remain independent from API-key model catalogs.
